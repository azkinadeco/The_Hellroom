# THE HELLROOM – asset contract

Generated by `blender/build_assets.py` (Blender 3.6, headless). Rebuild:

```
npm run assets                       # everything (~2.5 min on the 2015 MacBook)
npm run assets -- school_locker      # one or more assets by name
npm run assets -- props              # groups: textures props items entities ui
npm run assets -- --no-preview       # skip preview renders
```

Code layout: `hr_lib.py` (scene reset, MeshBuilder, materials, export, GLB
animation writer, previews), `props.py`, `items.py`, `entities.py`,
`textures.py` (numpy), `title.py`. Previews go to `blender/previews/`.
Entity previews are rendered from the re-imported GLB, so they show exactly
what ships.

## Global conventions

* Units are metres. Every GLB is +Y up (Three.js). The **front of every asset faces +Z in Three.js**
  (Blender -Y).
* Origin: the floor-level centre of the footprint unless an asset says otherwise.
* Static parts are merged into **one mesh node per asset** that has several materials. Three.js
  loads a node with several materials as a `Group` that has one `Mesh` child per material (named
  `<Node>_1`, `<Node>_2`, …). `getObjectByName('<Node>')` returns that Group.
* Materials are glTF metal/rough with no textures. Emissive materials are named `Emit*` and use
  `KHR_materials_emissive_strength` (strength 1.5–4). Opaque materials are single-sided. Glass and
  paper-thin materials are double-sided. Glass uses `alphaMode: BLEND`, and the materials named
  `*Glass` and `VHSWindow` are transparent.
* Metals are tuned for scenes **without an environment map**: metalness is 0.3–0.6, so steel stays
  grey instead of going black. If you add an envMap, they will get a little shinier.
* Hinged children (doors, leaves, clock hands) have their pivot exactly on the hinge or axis. They
  have identity rotation at rest, so you can set `rotation.y` (or `rotation.z` for clock hands)
  directly.

**Hinge directions in Three.js.** Every hinge rotates about local +Y, and the right-hand rule
applies:

* `DoorLeaf.rotation.y`:
  * positive values swing the leaf **away from the front** (toward −Z).
  * negative values swing it toward the viewer.
* `Door` (locker): **negative** values open it outward. Use about −1.9 rad for fully open, about
  −1.75 rad (100°) for a typical open position.
* `LeafL`: negative values open it toward the front.
* `LeafR`: positive values open it toward the front.
* Clock hands rotate about Z. Clockwise as seen from the front is **negative** `rotation.z`:
  `hand.rotation.z = -angle`.

**Fuse sockets.** Each `SlotN` is where the fuse centre goes, with the long axis vertical. Because
`item_fuse.glb` has its long axis on Y, it drops into a slot with identity rotation:
`slot.add(fuse)`, or copy the slot's world position.

## Entities (`assets/models/entity_*.glb`)

**Hierarchy.** The rigs are built from objects, not skins. The joint nodes are plain `Object3D`s:

```
Hips ─ Spine ─ Chest ─ Neck ─ Head
  │              ├─ ShoulderL ─ ElbowL ─ HandL
  │              └─ ShoulderR ─ ElbowR ─ HandR
  ├─ HipL ─ KneeL ─ FootL
  └─ HipR ─ KneeR ─ FootR
```

**Joints and geometry.**

* Each joint that has geometry owns one mesh child named `<Joint>_geo`. That child is a `Group`
  when it uses several materials.
* `Hips` is the only root node. The model origin is the floor between the feet.
* The model faces **+Z**. The **L joints are on +X**, which is the entity's own left.
* At rest every joint rotation is identity: the pose is upright with arms hanging straight down.
  Joint positions are relative to the parent.

**Animation tracks.**

* Every clip has a **rotation track on all 17 joints**, sampled at 30 fps with LINEAR
  interpolation. `Hips` also has a translation track. Any clip therefore fully overrides the pose,
  and cross-fading is safe.
* Looping clips have first key == last key, so they are seamless with `LoopRepeat`.
* For one-shots, use `LoopOnce` plus `clampWhenFinished` if you want to hold the last frame. The
  one-shots end back in the frame-0 pose of `Idle`.
* No clip has root motion: you move the entity in code. The exceptions are the Hips offsets
  described below for Run and Attack.
